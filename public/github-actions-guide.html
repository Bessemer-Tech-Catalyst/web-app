🚀 GitHub Actions CI Integration

Automatic PR preview scanning with Odyssey test orchestration

Architecture

When a PR is created or updated, the workflow automatically:

  1. Gets the PR's preview deployment URL
  2. Calls the deployed Odyssey app with a bearer token
  3. Starts an automated test scan of that URL
  4. Polls for completion (max 10 minutes)
  5. Exports the full test report
  6. Posts a comment on the PR with results
PR Created/Updated
↓
GitHub Actions triggered
↓
Deploy job publishes preview URL
↓
Odyssey workflow fetches URL
↓
POST /api/runs with Bearer token
↓
Poll GET /api/runs/[id] until done
↓
GET /api/runs/[id]/report.md
↓
Post idempotent PR comment

Key Features

✅ Automatic

Triggers on every PR open, sync, or reopen. No manual triggers needed.

🔒 Secure

Bearer-token auth protects API endpoints. Backward-compatible when token not set.

📊 Real Testing

Tests the actual PR preview deployment, not main branch.

⏱️ Timebound

10-minute max wait for scan completion. Budget-aware.

💬 Smart Comments

Idempotent PR comments update on rerun, never duplicate.

📈 Full Reports

Markdown reports include coverage, bugs, pass rates, healing actions.

Setup (5 Steps)

  1. Deploy Odyssey to a public URL (Vercel, AWS, etc.)
  2. Set env var on deployed app: ODYSSEY_CI_TOKEN=odyssey_sk_<random>
  3. Add GitHub Secrets: ODYSSEY_URL and ODYSSEY_CI_TOKEN
  4. Wire preview URL in workflow's "Get preview URL" step
  5. Create PR — workflow auto-runs and comments with results

For detailed setup with troubleshooting, see .github/ODYSSEY_CI_SETUP.md

API Endpoints

The workflow uses three endpoints, all protected by bearer token when ODYSSEY_CI_TOKEN is set:

POST /api/runs — Create scan

curl -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://pr-preview.example.com"}' \
  $ODYSSEY_URL/api/runs

Response: { id: "run_abc123" }

GET /api/runs/[id] — Poll status

curl -H "Authorization: Bearer $TOKEN" \
  $ODYSSEY_URL/api/runs/run_abc123

Response: { state: { report: {...} }, live: false } when done

GET /api/runs/[id]/report.md — Export report

curl -H "Authorization: Bearer $TOKEN" \
  $ODYSSEY_URL/api/runs/run_abc123/report.md

Response: Full Markdown report with coverage, bugs, risks, PRD traceability

Authentication Design

Backward Compatible:

  • If ODYSSEY_CI_TOKEN is NOT set: Auth disabled (current behavior — local dev works)
  • If ODYSSEY_CI_TOKEN is set: All callers must send Authorization: Bearer <token>

Why: Local development unaffected, production/staging protected, simple bearer-token design with no middleware overhead.

Testing the Integration

  1. Create a PR against the repo
  2. Watch Actions tab for "Odyssey Scan" workflow
  3. Wait for completion (~1-2 minutes)
  4. Check PR comments for Odyssey report with coverage, bugs, pass rate
  5. Push another commit to same PR
  6. Verify comment updates (not duplicated)
